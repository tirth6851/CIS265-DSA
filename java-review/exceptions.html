Exceptions

An exception is an event that disrupts normal program flow. Java uses try-catch-finally to handle it. Checked exceptions must be caught or declared; runtime exceptions do not.

try { int x = 10 / 0; } catch (ArithmeticException e) { System.out.println("Cannot divide by zero"); }

Key concepts

  • try – block where exception may occur.
  • catch – handle specific exception type.
  • finally – always executed (used for cleanup).
  • Throwing: throw new IllegalArgumentException("msg");

Code Question (little code)

try { int n = Integer.parseInt(text); } catch (NumberFormatException e) { System.out.println("Invalid number"); }

Code Question (no code)

What is the difference between throwing a checked exception and an unchecked exception? Checked must be declared or caught; unchecked (RuntimeException and its subclasses) are not enforced.

Theory Question

Explain the purpose of the finally block and whether it runs if an exception is not caught.

Practical Problems

  1. Write a method public static int safeDivide(int a, int b) that returns a / b if b != 0, otherwise throws an ArithmeticException with a descriptive message.
  2. Create a try‑catch‑finally block that reads an integer from the console (use a placeholder Integer.parseInt("abc") to simulate NumberFormatException), catches the exception, prints "Invalid input", and finally prints "Cleanup done".
  3. Define a custom checked exception class InsufficientFundsException (extends Exception) and a method withdraw(double amount) that throws it if amount > balance.
// Example solution for problem 1:
public static int safeDivide(int a, int b) {
    if (b == 0) throw new ArithmeticException("Cannot divide by zero");
    return a / b;
}

    InsufficientFundsException(String s) { super(s); }
